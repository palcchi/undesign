# Undesign UI Audit 001
Date: 2026-11-04
Mode: AFTER
Scope: Home/navigation, editor menus, Motion workspace, collaboration chat/comments, logo and icon system.
Method: source and test inspection on the Cue VM. A fresh visual click-through was blocked by a full root filesystem (7.6 MB free after the test attempt); findings below distinguish confirmed structural gaps from visual items requiring screenshot review.

## Findings

### 1. HIGH - Persistent team chat and comments are separate experiences
- Rules: R-05, R-20, R-31
- Evidence: `crates/ui-egui/src/live.rs` implements ephemeral cursor chat beside live pointers; `crates/ui-egui/src/comments.rs` implements document-anchored threaded comments. The parity notes state comments are local to the file and are not shared across collaborators.
- Problem: there is no single persistent group conversation where a team can chat, attach/refer to a design comment, reply, mention members, resolve a thread, and retain context together.
- Direction to review: one unified Activity/Discussion surface with message types (chat, anchored comment, reply, system activity), anchor previews, mentions, reactions, unread state, resolve/reopen, and project/file context. Preserve canvas pins as an entry point into the same thread rather than duplicating comment data.

### 2. HIGH - Motion exists as a timeline panel, not yet a complete motion workspace
- Rules: R-05, R-20, R-31
- Evidence: `crates/ui-egui/src/motion_panel.rs` currently provides composition selection, transport, a shared ruler/playhead, layer/property rows, stopwatch toggles, draggable keyframes, zoom, and numeric keyframe editing. It is exposed in a side panel and a bottom dock.
- Problem: this is a useful foundation, but the interface does not yet present the full After Effects-style directing workflow as a dedicated workspace. The inspected UI does not expose a Graph Editor/curve workspace, robust timeline track organization, or a broader effects/compositing workflow in the main Motion surface.
- Direction to review: dedicated Motion mode with preview/canvas, project/layer stack, full-width timeline, transport/timecode, keyframe selection, graph/easing editor, track controls, and contextual properties. Use After Effects as an interaction reference, not a pixel-for-pixel clone. Preserve the existing motion document model and undoable engine commands.

### 3. MEDIUM - Home is currently a Recents/Online launcher, not a workspace dashboard
- Rules: R-24, R-05, R-20
- Evidence: `crates/ui-egui/src/home.rs` defines only Recents and Online as home sections. The Recents view offers New design, New board, Import file, Join team, Getting started, open files, and recent files. `home_tests.rs` explicitly verifies the two-section navigation.
- Problem: there is no first-class Projects, Shared with me, Favorites, Trash, team/workspace switcher, or project-level organization in the home navigation. Adding those labels before real destinations exist would violate R-24.
- Direction to review: establish a real workspace hierarchy first, then add navigable Home sections only when their data/actions are implemented. Keep Recents as the fast-return surface.

### 4. MEDIUM - Icon family needs a visual consistency and semantic audit
- Rules: R-04, R-31
- Evidence: `app_glyphs.rs` contains a hand-drawn clean-room glyph family and compatibility mapping; `icons.rs` contains the broader icon renderer. The code includes dedicated Home, Motion, Comment, and other product glyphs.
- Problem: source inspection confirms multiple icon rendering paths, but cannot prove optical consistency or identify which icons look poor without a live screenshot at actual toolbar sizes. A broad replacement with a generic icon library would risk losing the existing custom visual language.
- Direction to review: audit by role and actual size, normalize optical weight, stroke/filled behavior, baseline, padding, selected/hover/disabled states, and remove decorative or redundant icons. Keep icons semantically distinct and use labels/tooltips where a glyph is ambiguous.

### 5. MEDIUM - Logo and app mark need a deliberate identity review
- Rules: R-20, R-23, R-31
- Evidence: `theme.rs` paints a two-tone “Undesign” wordmark using the brand font and loads a 64x64 monochrome app icon from `assets/app-icon/undesign-64-mono.png`.
- Problem: the implementation is present, but there is no approved identity brief in the inspected project direction document; that document describes the assistant role, not the product's brand identity. Aesthetic quality cannot be fairly graded without seeing the mark at app-icon, sidebar, and wordmark sizes.
- Direction to review: inspect the existing mark at 16/24/32/64 px and on light/dark surfaces before proposing any redesign. Do not generate a replacement logo asset until the concept, shape, and color direction are approved.

### 6. HIGH - Verification is currently blocked by storage exhaustion
- Rules: R-35
- Evidence: `cargo test --workspace` exited 101 after Rust reported `No space left on device`. The VM root filesystem was at 100%; `/workspace/undesign/target` alone occupied about 20 GB. This is an environment/storage failure, not evidence of a source-code test failure.
- Problem: the restored UI cannot yet be certified by a clean full test run or visual click-through. The running app process is present, but no new visual run was completed during this audit.
- Direction to review: inspect disk consumers and agree on a safe cleanup plan before deleting build artifacts or caches; then rerun targeted UI tests, workspace tests, and screenshot/click-through checks.

## Existing functionality to preserve
- Figma-style editor foundations: File/Edit/View/Object/Arrange/Plugins menus, Design/Motion/Developer Mode, canvas, layers, assets, prototype/inspect surfaces.
- Motion model and current timeline operations.
- Anchored comments with threaded replies, mentions, reactions, resolve state, and comment panel.
- Live collaboration presence, cursors, sharing, and ephemeral cursor chat.
- Custom clean-room app glyphs and current logo assets until a replacement is approved.
